# MayOS 0.5.4-beta.1 · 集中验收与低频发布策略

**状态：仅在 `develop/0.5.4-beta.1` 开发，未公开发布。** 公开的最新 Pre 是 `0.5.4-pre31`；原 0.5.5-pre1 未发布计划取消。

## 版本冻结规则

- 日常代码提交、修 Bug、UI 优化及补测试只增加 Git commit SHA，不递增 Beta 版本号，也不自动发布 ISO。
- 当前内部构建身份固定为 `0.5.4-beta.1-dev`；同一代码 SHA 完整验收后才集中发布 `0.5.4-beta.1`。
- 只在完成新的完整开发里程碑、显著功能集成或重要安全修复并重新全面验收后，才考虑 `beta.2`。禁止按日期或每次提交升级。
- 不覆写历史 `0.5.4-pre31` 标签或已发布文件；不提前更新官网为不存在的 Beta 下载。

## 同一 SHA 的发布门禁

- [ ] MayKernel64 和 Linux64 编译通过，从同一真实 GRUB ISO 经 QEMU 分别成功启动。
- [ ] Linux64 E1000、E1000e、VirtIO-net 的 DHCP、路由、TLS1.3 可信/不可信 CA 测试全部通过。
- [ ] Bing JPEG、RGB565、原子缓存、断网保留旧图、每日期缓存、目录符号链接保护通过自动化测试。
- [ ] Linux64 壁纸服务在 QEMU 联网实测；MayKernel 缺少的可信 TLS/大图存储必须在说明中如实声明。
- [ ] 默认 RAM-only 模式无磁盘写入、标记 ext4 持久化 A/B 快照及断电恢复测试通过。
- [ ] 更新、Explorer、任务管理器、Dock、自动分辨率/缩放、安装器或 Live 的实际功能不退化；验证主分支 pre31 的更新内容。
- [ ] 核验镜像版本标识、BIOS/UEFI 能力、SHA-256、真实 QEMU 截图和日志；只发布与描述一致的镜像。
- [ ] 所有重要 CI 对同一最终 SHA 成功；测试进行中或失败不视为通过。

未满足以上要求前不创建 Beta Release，不增加 Beta 版本号。
