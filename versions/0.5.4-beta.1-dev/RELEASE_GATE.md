# MayOS 0.5.5-pre1 · 集中验收发布门槛

**状态：仅开发分支（develop/0.5.5-pre1），不是已发布版本。**

## 版本策略

- 开发中的每个修复提交使用 GitHub commit/PR，不创建新的 `preN` 标签、Release 或 ISO 下载链接。
- 仅当完整功能矩阵通过且实际 ISO 可启动时，将 `0.5.5-pre1-dev` 改为 `0.5.5-pre1`，从独立 `versions/0.5.5-pre1-dev/` 源码打包为 `versions/0.5.5-pre1/`，发布 **单个** 0.5.5-pre1 预览版。
- 后续预览版不是自动每阶段递增。只对影响数据安全、启动或联网的阻塞问题才考虑 pre2；一般界面和功能修改累计到下一正式验收批次。
- 绝不以改版本号代替真实功能实现、QEMU 运行截图或发布产物。
- 在 0.5.5-pre1 发行前，将 PR #58（Linux 多网卡）和 PR #59（Bing 壁纸）同主分支逐项整合，确认当前主分支 pre31 已发布的更新页和 Explorer 功能没有回归。

## 发布硬性检查（所有项目均需同一 SHA）

- [ ] MayKernel 64 位 freestanding GCC 构建通过，原有桌面和本地存储数据不回归。
- [ ] Linux64 官方内核源码构建通过，驱动配置含 E1000、E1000e、VirtIO-net。
- [ ] 从同一 ISO 经真实 QEMU GRUB 分别启动 MayKernel 和 Linux64；不得仅使用 QEMU -kernel 快捷方式。
- [ ] 三个独立 QEMU NIC 均通过 DHCP、默认路由、TLS1.3、可信 CA 接受与未知 CA 拒绝。
- [ ] Bing 解码、1280×720 RGB565 和原子缓存测试通过；Linux64 实际服务进程和断网回退测试通过。
- [ ] MayKernel Bing 自动联网只有在可信 TLS、时钟、熵源和较大图片缓存验收通过后才能标记完成；否则在发行说明中写明不支持。
- [ ] RAM-only 模式不写入无标记磁盘；仅用户显式选择并标记的 ext4 数据卷可用于持久化。
- [ ] 原子快照和突发断电恢复 QEMU 回归通过，并保留日志/散列。
- [ ] 更新、Explorer、Dock、任务管理器、自动显示缩放各关键路径不回归。
- [ ] 实际产出 ISO 并计算 SHA-256，清晰标出是否包含安装器、UEFI/BIOS 启动能力和已知限制。
- [ ] 网站版本目录和可验证下载在 Release 发布后同步更新，而非提前展示预期版本。
