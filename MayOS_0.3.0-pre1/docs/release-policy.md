# MayOS 发布约定

## 版本与发布通道

- 小更新发布为预发布版，格式为 `v主版本.次版本.修订版本-preN`，例如
  `v0.3.0-pre2`。同一版本线每次小更新递增 `preN`，并在系统“关于”、
  Linux `os-release`、官网和发布附件中使用相同版本号。
- 大更新发布为正式版，格式为 `v主版本.次版本.修订版本`，不带 `pre`。
  新功能集合通常提升次版本号；不兼容的大改动提升主版本号。正式版必须先
  更新产品版本号，并提供对应 ISO / 发布包、SHA-256、第三方源码与启动验证。
- 普通 Git 提交不自动创建 Release。完成一组小更新后手动运行源码预发布工作流；
  大更新使用正式发布清单和完整产物工作流。
- GitHub Releases 只保留最新一项。新 Release 完整创建后再删除旧 Release；
  Git 标签和提交历史保留，便于追溯与重建。
- 不再使用 `-source.1` 这类二次后缀。源码快照的性质写入标题和说明，版本号本身
  始终使用 `-preN` 或正式版本格式。
