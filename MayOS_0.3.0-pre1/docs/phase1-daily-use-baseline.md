# MayOS 1.0 日用化 · 第一阶段：启动与稳定性基线

状态：**代码审查与持续验证阶段**；尚未达到“日用系统”标准。此阶段不改现有 macOS 桌面布局、Material Design 3 组件、窗口视觉、指针与既定交互。

## 阶段目标

首先让自研 MayKernel 的 x86_64 启动与基础功能在相同环境下能够反复验证。**阶段一完成不等于 MayOS 1.0 可以日用。**

### 交付门槛

- [ ] 每次 PR 的主内核构建成功，确认生成 ELF64 x86-64，产出可启动 ISO 及 SHA-256。
- [ ] 至少验证 BIOS + OVMF UEFI 两条完整固件 → GRUB → 内核 → 桌面路径；不能只依赖 `qemu -kernel`。
- [ ] 冷启动与重启各验证多次，保留串口日志和可复现失败记录。
- [ ] 文件创建、修改、关闭后再次启动并读回；隔离测试磁盘，检查未识别数据盘不被破坏。
- [ ] 键盘、鼠标、窗口操作、设置持久化和桌面功能回归通过。
- [ ] 异常与内存边界处理有可测证据：异常向量、分页/地址映射、保留内存跳过、分配失败处理。
- [ ] 记录连续运行和高频文件操作的稳定性测试结果；不能把短时启动成功当成可靠性证明。
- [ ] 发布的 ISO、截图、真实 QEMU 录屏、测试报告和源码提交 SHA 严格对应。
- [ ] 任何失败均阻止将版本宣称为稳定版或日用版。

## 当前可自动执行的基线

仓库 `.github/workflows/maykernel-phase1.yml` 在 Ubuntu 24.04 上安装构建工具，构建自研 x86_64 ELF 与混合 ISO，核对 ELF 架构并调用原有 `make test`（其中包含 QEMU 与桌面烟雾测试），在成功或失败时收集证据。

**注意：** 此工作流目前不等同于 BIOS / UEFI 完整双启动验证；`make test-dual` 和 `make test-uefi` 还依赖完整 Linux 双启动构建或既有产物，需要独立构建与核验。运行 GitHub Actions 后才可填报真实结果；不以本文件创建成功代替测试通过。

## 阶段二进入条件

上述验证门槛均获得可复现的构建输出及测试记录；若未达标，先修复启动、内存、文件系统与输入问题，不提前新增影响稳定性的外观功能。

## 不改变的约束

保持已确定的类 macOS 桌面结构与 Google Material Design 3 风格；任何 UI 改动需先有设计依据与一致性校验。不得以静态样机、合成视频冒充系统真实运行录屏。未经实测不得宣布 ISO 已稳定、支持实体机或达到日用标准。
