# MayOS 1.0 日用化 · 第一阶段：启动与稳定性基线

状态：**代码审查与持续验证阶段**；尚未达到“日用系统”标准。此阶段不改现有 macOS 桌面布局、Material Design 3 组件、窗口视觉、指针与既定交互。

## 阶段目标

首先让自研 MayKernel 的 x86_64 启动与基础功能在相同环境下能够反复验证。**阶段一完成不等于 MayOS 1.0 可以日用。**

## 当前可自动执行的基线

仓库 `.github/workflows/maykernel-phase1.yml` 在 Ubuntu 24.04 上安装构建工具，构建自研 x86_64 ELF 与混合 ISO，核对 ELF 架构并调用原有 `make test`（其中包含 BIOS QEMU 与桌面烟雾测试）。随后执行 `uefi_smoke.py --custom-only` 进行实际 OVMF 固件启动与冷启动持久化校验，再由 `phase1_soak.py` 在同一份 ISO 上执行 BIOS 与 UEFI 各 3 次独立冷启动，核对 MayFS 数据完整性。之后在上传普通 ISO 证据之后，重新构建**仅用于测试且会主动触发错误的诊断 ISO**，使用 `exception_smoke.py` 进行 QEMU 无效指令 `#UD` 故障注入，验证串口日志包含异常向量、错误码与 RIP。诊断 ISO 从不作为正式 ISO 或普通 ISO 附件交付。构建日志、JSON、图片、正常 ISO 与哈希保留为 GitHub Actions 附件；每次提交必须以实际 Actions 运行结果为准。

**本轮经核验的证据：** [Actions #43557182839](https://github.com/ZhongYeMay/MayOS/actions/runs/43557182839) 验证 ELF64、BIOS 基础回归、OVMF UEFI 冷启动、同一 ISO 下 BIOS/UEFI 各 3 次冷启动及 MayFS 完整性，并在另行构建的诊断 ISO 内验证 #UD 向量 6、错误码与 RIP 日志。该工作流不等同于 Linux + MayKernel 双启动镜像的完整矩阵；`make test-dual` 和 `make test-uefi` 仍依赖完整 Linux 构建或既有产物。未执行的项目不可填写为通过。

## 2026-11-14 新增压力与损坏保护验证

- **已核验运行：** [GitHub Actions #43558207451](https://github.com/ZhongYeMay/MayOS/actions/runs/43558207451)，对应的已测试代码提交 `5697f1917fca6da5f45807f2d4cd30f844af267b`。
- **内存：** 新增非图形化 `memstress`，每次内部 16 轮 × 128 页，检查分配清零、读写隔离、碎片化后重用、重复/无效释放、防泄漏；该运行完成 4 次命令。**不包含全内存耗尽或长期稳定性证明。**
- **MayFS：** 10 次独立文件写入，逐次检查校验和，15 秒运行存活，OVMF UEFI 冷启动读取与整盘 SHA-256 比对。
- **损坏保护：** 在抛弃式测试盘上篡改校验覆盖内容，两次 BIOS 启动均拒绝挂载、回退 RAM 并保持原盘全部字节不变。**未提供自动修复或断电写入恢复。**
- **回归：** 原有 BIOS/UEFI 启动、GUI、MayFS 测试及独立 #UD 异常诊断均通过。
- **附件：** 该 Actions 运行保存可下载的正常 ISO、真实 QEMU 截图、JSON、串口日志及专用故障诊断日志。诊断 ISO 不在正常运行附件中。
- **其他 CI：** `Fast settings / MayFS compiler checks` 的官网版本号推广预演因缺少旧字符串 `0.4.1-pre1` 失败，与上述阶段一主验证无关，后续需要单独处理。

## 阶段二进入条件

上述验证门槛均获得可复现的构建输出及测试记录；若未达标，先修复启动、内存、文件系统与输入问题，不提前新增影响稳定性的外观功能。

## 不改变的约束

保持已确定的类 macOS 桌面结构与 Google Material Design 3 风格；任何 UI 改动需先有设计依据与一致性校验。不得以静态样机、合成视频冒充系统真实运行录屏。未经实测不得宣布 ISO 已稳定、支持实体机或达到日用标准。
