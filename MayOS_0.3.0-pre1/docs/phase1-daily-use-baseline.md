## 当前可自动执行的基线

仓库 `.github/workflows/maykernel-phase1.yml` 在 Ubuntu 24.04 上安装构建工具，构建自研 x86_64 ELF 与混合 ISO，核对 ELF 架构并调用原有 `make test`（其中包含 BIOS QEMU 与桌面烟雾测试）。随后执行 `uefi_smoke.py --custom-only` 进行实际 OVMF 固件启动与冷启动持久化校验，再由 `phase1_soak.py` 在同一份 ISO 上执行 BIOS 与 UEFI 各 3 次独立冷启动，核对 MayFS 数据完整性。之后在上传普通 ISO 证据之后，重新构建**仅用于测试且会主动触发错误的诊断 ISO**，使用 `exception_smoke.py` 进行 QEMU 无效指令 `#UD` 故障注入，验证串口日志包含异常向量、错误码与 RIP。诊断 ISO 从不作为正式 ISO 或普通 ISO 附件交付。构建日志、JSON、图片、正常 ISO 与哈希保留为 GitHub Actions 附件；每次提交必须以实际 Actions 运行结果为准。

**本轮经核验的证据：** [Actions #43557182839](https://github.com/ZhongYeMay/MayOS/actions/runs/43557182839) 验证 ELF64、BIOS 基础回归、OVMF UEFI 冷启动、同一 ISO 下 BIOS/UEFI 各 3 次冷启动及 MayFS 完整性，并在另行构建的诊断 ISO 内验证 #UD 向量 6、错误码与 RIP 日志。该工作流不等同于 Linux + MayKernel 双启动镜像的完整矩阵；`make test-dual` 和 `make test-uefi` 仍依赖完整 Linux 构建或既有产物。未执行的项目不可填写为通过。

## MayFS 双快照与恢复（2026-11-14）

已实测代码 SHA：`a534a9c33ff1a1750538c3eb4dfa2fc0d81e948c`。完整 GitHub Actions 运行：
https://github.com/ZhongYeMay/MayOS/actions/runs/43573603201

- 传统 MayFS 仍使用主快照 LBA 0–511；空闲或已识别的备份区域使用 LBA 512–1023。通过 ATA IDENTIFY 检查容量，**没有足够容量或备用区域含未知数据时保持原单槽模式，不擅自覆写未知区域**。
- 两个快照分别验证文件区校验和及文件结构；新版头部增加 `MAY2` generation 和反码，允许两份均有效时选择较新的版本。无 generation 的传统旧盘仍能读取。
- 保存时先写非当前有效槽的全部数据，再写该槽头部并 FLUSH CACHE，之后镜像到另一槽；恢复后首次写入先修复坏掉的主槽。两份均损坏时禁止自动格式化，回退 RAM。
- QEMU 模拟故障测试已通过：较新备份覆盖较旧主槽、旧版盘兼容迁移、主槽数据破坏后读回、后续保存完成双副本修复、备用槽部分写入损坏时保留完好的主槽、双副本损坏时原磁盘零写入。
- 原有 GUI、设置持久化、BIOS/OVMF 冷启动、内存/MayFS 压力及故障诊断均再次通过。
- **边界：**这属于离线模拟不同写入中断状态后，用真实 QEMU 冷启动验证恢复机制；还未对模拟器进行随机时刻强制断电，也未证明实体磁盘缓存、电源故障或长时高负载可靠性。不保证已经实现真正的事务性文件系统。剩余工作包含断电故障注入、完整磁盘边界与内存不足处理。

## 2026-11-14 · QEMU SIGKILL 模拟断电与磁盘边界

- **经验证源代码提交：** `ae3b4d0802d910ec5d18bef383796fc1991ede08`。
- **完整成功运行：** [Actions #43576588178](https://github.com/ZhongYeMay/MayOS/actions/runs/43576588178)（包含正常 ISO、JSON、真实 QEMU 截图、诊断日志；故障注入镜像独立构建，禁止用于发行）。
- **真实运行时中断写盘：** 只有在 `FS_POWERLOSS_SELFTEST=1` 的隔离诊断 ISO 中编译故障检查点。对一次实际 ATA 写入，在备用快照仅写入 32 个数据扇区和备用快照完整写入且执行 ATA FLUSH CACHE 后分别让客户机停住，由宿主 SIGKILL QEMU（不是优雅关机），然后由**正常 ISO** 冷启动进行验收。
- **实际结果：** 在部分写入时恢复原先保存的数据；在备用快照已提交、主快照尚未更新时恢复新的数据。两个场景均验证正常 ISO 的冷启动与磁盘哈希读后不变，并确认普通 ISO 完全不含断电故障注入代码。
- **磁盘容量和邻域保护：** 备用区域含未知外部数据时单槽写入且该区域字节完全不变；正好 512 扇区的传统 MayFS 仍能保存与冷启动读回；511 扇区容量不足时仅使用 RAM 并保留全部磁盘字节。
- **所有原有基线：** 64 位构建、GUI/设置、BIOS+UEFI 6 次冷启动、5 次 memstress、12 次文件写入、60 秒运行检查、双快照故障模拟及独立 #UD 异常诊断在本次均通过。
- **限制：** 此为带两种确定性故障切点的 QEMU 进程强杀，不等价于断开实体设备的电源，也未证明磁盘控制器真实断电后的写缓存可靠性。随机中断时间、多次复杂交错写入、小时级耐久度、可恢复错误码、跨硬件驱动等仍待完成。不能宣称已经达到稳定版、日用版或事务性文件系统的要求。
